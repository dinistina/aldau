# Aldau — план проекта

Детектор мошеннических объявлений для OLX.kz / Kolesa.kz / Krisha.kz (русский и казахский).
Fable — учитель, маленькая модель — ученик, Telegram-бот — интерфейс.

Каждая фаза — отдельная сессия Claude Code. Не переходить к следующей, пока тесты текущей не зелёные.

---

## Фаза 0 — Каркас репозитория
**Цель:** пустой, но рабочий проект.
- `pyproject.toml`, структура папок из CLAUDE.md, `.gitignore`, `.env.example`
  (`LLM_PROVIDER`, `LLM_MODEL`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`,
  `TELEGRAM_BOT_TOKEN`)
- `schema.py`: модель объявления — `id, source (olx/kolesa/krisha), category, title, text, price_kzt,
  city, photos (пути), seller_info (опционально), lang (ru/kk), label (scam/legit/unknown)`
- Модель метки учителя: `label, risk_score (0–1), signals: list[str], explanation_ru: str`
- GitHub Actions: запуск `ruff` и `pytest` на каждый push
- README-заглушка на английском

**Готово, когда:** `pytest` проходит, CI зелёный.

## Фаза 1 — Данные
**Цель:** собрать и разметить реальные данные (это делаешь ТЫ, код только помогает).
- `collect.py`: CLI, куда вставляешь текст объявления, цену, категорию — он сохраняет в `data/raw/ads.jsonl`
- Собрать вручную ~200–300 реальных объявлений: обычные + подозрительные
  (источники мошеннических примеров: новости о заблокированных объявлениях, памятки OLX и прокуратуры,
  жалобы в соцсетях — переписывать своими словами структуру, без личных данных)
- `features.mask_pii()` — маскирует телефоны, email, ссылки, имена
- **Gold set:** 100 объявлений размечаешь сам, вручную. Это эталон для честной оценки, его никогда не
  видит обучение.

**Готово, когда:** есть `data/raw/ads.jsonl` и `data/gold/gold.jsonl`, тест на маскировку PII проходит.

## Фаза 2 — Признаки
**Цель:** «ручные» сигналы мошенничества, понятные человеку.
- Цена относительно рынка: медиана по категории и городу → `price_ratio`
  (слишком дёшево = красный флаг)
- Регулярки (ru + kk): предоплата / бронь / задаток, «пишите в WhatsApp/Telegram», срочность
  («только сегодня», «уезжаю»), доставка из-за границы
- `photos.py`: перцептивный хеш (pHash) фото, поиск одинаковых фото в разных объявлениях
- Небольшой EDA-ноутбук: распределения признаков для scam vs legit

**Готово, когда:** тесты на каждую регулярку и на поиск дубликатов фото проходят.

## Фаза 3 — Учитель (сначала бесплатная модель, потом Fable)
**Цель:** большая модель размечает объявления и объясняет решение.
- `llm.py`: единый клиент для gemini / openrouter / ollama / anthropic, выбор через `LLM_PROVIDER`
- Разработка и отладка — на бесплатной модели (Gemini Flash), по ~10 объявлений за запрос
- `teacher.py`: промпт с описанием типичных схем мошенничества в Казахстане, на вход — текст + признаки
  из фазы 2, на выход — строгий JSON по схеме из фазы 0
- Версия промпта хранится в коде (`PROMPT_VERSION`), кеш на диске, `--limit`, повтор при ошибках
- **Проверка учителя:** прогнать его на gold set и посчитать, насколько он совпадает с твоей разметкой.
  Если плохо — улучшать промпт, а не подгонять данные.
- Разметить все не-gold объявления

**Готово, когда:** есть отчёт «точность учителя на gold set» и `data/labeled/teacher_labels.jsonl`.

## Фаза 4 — Синтетические данные
**Цель:** добрать данные, особенно на казахском и для редких схем.
- `synth.py`: текущий учитель (`LLM_PROVIDER`, через `llm.py`) генерирует реалистичные
  мошеннические и нормальные объявления по разным категориям / городам / языкам с заданным
  разнообразием
- Дедупликация (почти одинаковые тексты удалять)
- Синтетика — **только в train**. Тест, что ни одно синтетическое объявление не попало в gold.

**Готово, когда:** ~1000–2000 синтетических примеров, тест на отсутствие утечки проходит.

## Фаза 5 — Ученик
**Цель:** обучить маленькую модель, которая работает без API.
- `train_baseline.py`: TF-IDF + числовые признаки → LogisticRegression (быстрый baseline)
- `train_student.py`: дообучение `cointegrated/rubert-tiny2` (можно на CPU или в Google Colab)
- Обучение на метках учителя (+ синтетика), подбор порога по PR-кривой
- Эксперимент: с синтетикой vs без синтетики — помогает ли она?

**Готово, когда:** сохранённые модели в `models/`, метрики в `reports/`.

## Фаза 6 — Бенчмарк
**Цель:** главная таблица для README.
- `evaluate.py` на gold set для: бесплатный учитель, Fable-учитель, Haiku zero-shot, baseline,
  rubert-tiny2 (обученный на метках бесплатной модели vs на метках Fable), каскад
- Строки Fable-учитель, Haiku zero-shot и «ученик на метках Fable» — **опциональные**: если в `.env`
  нет `ANTHROPIC_API_KEY` (или нет меток Fable), `evaluate.py` их пропускает и пишет в отчёте «not run»
- Главный вопрос исследования: насколько более сильный учитель делает лучше маленького ученика?
- Метрики: precision, recall, F1, PR-AUC, стоимость за 1000 объявлений, задержка
- Анализ ошибок: 10 худших промахов ученика и почему
- Графики (PR-кривые, confusion matrix) в `reports/`

**Готово, когда:** `reports/benchmark.md` с таблицей и графиками.

## Фаза 7 — Каскад и Telegram-бот
**Цель:** продукт, которым можно пользоваться.
- `cascade.py`: ученик → если риск в «серой зоне» (например, 0.35–0.65) → Fable
- Бот на aiogram: пользователь присылает текст объявления (+ фото по желанию) и цену →
  получает риск (🟢/🟡/🔴), 2–4 причины на русском, совет что проверить, дисклеймер
- Команды: `/start`, `/help`, `/stats`
- Логи запросов в SQLite (без личных данных), кнопки «верно / неверно» для сбора обратной связи

**Готово, когда:** бот работает локально, есть демо-гифка.
