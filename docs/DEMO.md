# Демо на Technopark EXPO (14 декабря 2026)

## Запуск бота одной командой

На MSI, в PowerShell:

```powershell
cd F:\projects\aldau; .venv\Scripts\python.exe -m aldau.bot
```

Появится строка «Бот запущен (учитель в серой зоне, до 10 запросов в день)», затем
`Run polling for bot @aldau_project_bot`. Всё, можно писать боту с телефона. Остановить — Ctrl+C.

Варианты:

```powershell
cd F:\projects\aldau; .venv\Scripts\python.exe -m aldau.bot --no-teacher
```

`--no-teacher` — ни одного запроса к Gemini (если квота кончилась или интернет слабый).

Что нужно для запуска (проверено 2026-11-27 в новом процессе, оба режима):
- `models/baseline.joblib` — модель (если её нет, бот пишет «Нет модели: сначала
  python -m aldau.train_baseline»);
- `.env` с `TELEGRAM_BOT_TOKEN` (без него бот пишет «TELEGRAM_BOT_TOKEN в .env не задан»),
  для учителя ещё `GEMINI_API_KEY`, `LLM_PROVIDER=gemini`, `LLM_MODEL`;
- интернет. Порт и сервер не нужны: бот сам спрашивает Telegram (long polling), поэтому работает
  и через раздачу с телефона.

Бот должен быть запущен **только в одном месте**: если запустить второй экземпляр с тем же
токеном, Telegram ответит `Conflict: terminated by other getUpdates request`. Закройте лишний.

## Если нет интернета — запасное демо

Всё работает на ноутбуке без сети (локальная модель + регулярки):

```powershell
cd F:\projects\aldau; .venv\Scripts\python.exe -m aldau.web
```

Страница http://127.0.0.1:8000: вставить объявление, нажать «Проверить». Ответ тот же, что у бота.

```powershell
cd F:\projects\aldau; .venv\Scripts\python.exe -m aldau.check --file docs/demo_ads.txt
```

Все заготовленные объявления подряд в консоли. Без `--file` — вставить своё и закончить
строкой `---`. Флаг `--teacher` у обоих включает учителя для 🟡 (нужен интернет).

### №10 — показ каскада: ученик не уверен и спрашивает учителя

Это объявление **подобрано**, чтобы попасть в 🟡 (решение владельца 2026-11-27): оно показывает
механизм, а не точность, и так и надо говорить. Живого сомнительного объявления вне gold не нашлось:
из 25 неразмеченных живых объявлений 22 уже в gold, оставшиеся 3 уверенно 🟢. Из 7 написанных
кандидатов 5 модель оценила уверенно (0–5 % или 86–100 %); в 🟡 попали только два, где правило
«продавец не может встретиться» подняло уровень. Выбран Samsung.

Проверено 2026-11-27 через обработчик бота с настоящим учителем (`gemini-3.5-flash`, промпт v2,
1 запрос):
1. сразу: 🟡, «Уровень поднят правилом…», «⏳ Идёт углублённая проверка, ответ обновится…»;
2. через 20 с сообщение обновилось: «Углублённая проверка не успела ответить — ответ локальной
   модели» — учитель отвечал дольше 20 с; запрос доделался в фоне и записал ответ в кеш;
3. повтор (ответ из кеша, без нового запроса): 🟢 «Оценка углублённой проверки: 20 % (локальная
   модель: 7 %)», учитель: *«Продавец предлагает встретиться лично после возвращения из командировки
   либо отправить товар курьером с оплатой при получении. Требований предоплаты или подозрительных
   ссылок нет.»*

Важно для выставки:
- ответ учителя на №10 **уже в кеше** (`data/cache/live_teacher.jsonl`), поэтому на выставке
  сообщение обновится сразу, без интернета и без запроса. Честно сказать: «ответ учителя на это
  объявление сохранён; новое объявление пойдёт к учителю вживую, это может занять до 20 секунд»;
- новое 🟡-объявление от посетителя пойдёт к Gemini вживую — может не успеть за 20 с (как в
  первой попытке) или упереться в лимит; бот тогда ответит локальной моделью с пометкой и не упадёт.

## Перед выставкой

- 11.12 — заморозка кода, 12–13.12 — репетиция, в том числе офлайн (`aldau.web`).
- Утром 14.12: `.venv\Scripts\python.exe -m pytest -q` (всё зелёное), запустить бота, отправить
  ему №1 и №3 с телефона, проверить ответы.
- Отключить сон ноутбука при закрытой крышке / по таймеру — иначе бот перестанет отвечать.
- Логи — `data/bot.db` (замаскированный текст объявления, риски, отзыв; данных о пользователях нет).
- Если учитель недоступен (лимит, 503, нет интернета) или не ответил за 20 с, бот отвечает
  локальной моделью с пометкой «углублённая проверка недоступна». Бот не падает.
