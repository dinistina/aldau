# Learning log — что построено и почему

Короткие объяснения после каждой фазы. Цель — чтобы автор мог рассказать о любой части проекта
на собеседовании.

## Фаза 0 — Каркас репозитория (2026-11-15)

### Что построено
- `pyproject.toml` — описание проекта и зависимостей.
- `src/aldau/schema.py` — две модели данных: `Ad` (объявление) и `TeacherLabel` (ответ учителя).
- `tests/test_schema.py` — тесты на эти модели.
- `.github/workflows/ci.yml` — автоматическая проверка на GitHub при каждом push.
- `.gitignore`, `.env.example`, README-заглушка, пустые папки `data/` и `notebooks/`.

### Зачем это нужно и ключевые понятия

**`pyproject.toml` и `pip install -e .`**
Это современный стандарт описания Python-проекта (вместо `setup.py` и `requirements.txt`).
Флаг `-e` (editable) ставит проект «ссылкой»: меняешь код в `src/` — изменения сразу видны,
переустанавливать не надо. Благодаря установке можно писать `from aldau.schema import Ad`
из любого места, включая тесты.

**src-layout (`src/aldau/`, а не просто `aldau/`)**
Если пакет лежит в корне, Python может импортировать его прямо из папки, даже если он не
установлен, и тесты проходят «случайно». С `src/` тесты работают только с установленным пакетом —
то есть проверяют то же самое, что получит пользователь.

**Необязательные зависимости (`[project.optional-dependencies]`)**
`torch` и `transformers` весят гигабайты. Они вынесены в группы (`ml`, `llm`, `bot`, `photos`),
чтобы CI и обычная разработка ставились за секунды. Нужная группа ставится так:
`pip install -e ".[dev,ml]"`.

**Pydantic вместо dataclass**
Выбор был: обычный `dataclass` или `pydantic.BaseModel`.
- `dataclass` — встроен в Python, но типы в нём только «подсказки»: `Ad(source="avito")` или
  `risk_score=1.7` пройдут без ошибки.
- `pydantic` — проверяет типы и значения при создании объекта и умеет читать/писать JSON
  (`model_dump_json`, `model_validate_json`).
Выбран pydantic, потому что учитель (LLM) возвращает JSON, а LLM иногда ошибается в формате.
Нам нужно, чтобы кривой ответ падал сразу с понятной ошибкой, а не попадал в обучающие данные.
Цена — одна лишняя зависимость.

**`Literal["scam", "legit", "unknown"]`**
Тип «только эти строки». Опечатка вроде `"scum"` станет ошибкой валидации, а не тихим третьим
классом в данных.

**Почему у `Ad` есть `unknown`, а у `TeacherLabel` нет**
`Ad.label` — это человеческая разметка; пока объявление не размечено, оно `unknown`.
Учитель же обязан принять решение (scam или legit), а свою неуверенность он выражает числом
`risk_score` от 0 до 1. Именно это число потом используется в каскаде: если риск в «серой зоне»,
ученик спрашивает учителя.

**Тесты (`pytest`) и `parametrize`**
`@pytest.mark.parametrize` запускает один тест с разными входными данными — так одним тестом
проверяется, что отклоняются и неверный `source`, и неверный `lang`, и отрицательная цена.
Отдельный тест проверяет, что казахский текст (буквы ә, ғ, қ, ң, ө, ұ, ү, һ, і) не портится
при сохранении в JSON и чтении обратно.

**Линтер `ruff`**
Проверяет код без запуска: неиспользуемые импорты, порядок импортов, устаревший синтаксис,
типичные ошибки. Работает за миллисекунды.

**CI (GitHub Actions)**
На каждый push GitHub поднимает чистую Linux-машину, ставит проект и запускает `ruff` и `pytest`.
Смысл: «у меня на ноутбуке работает» ничего не доказывает, а зелёная галочка в репозитории —
доказывает, что проект собирается с нуля. Для работодателя это признак аккуратной разработки.

**`.env` и `.env.example`**
Ключи API — это секреты. Они лежат в `.env`, который указан в `.gitignore` и никогда не попадает
в git. В репозитории лежит только `.env.example` — образец без значений, чтобы было понятно,
какие переменные нужны.

**`.gitkeep`**
Git не хранит пустые папки. Чтобы структура `data/raw`, `data/gold` и т. д. была в репозитории,
в каждую кладётся пустой файл `.gitkeep`. Сами данные при этом игнорируются.

### Вопросы, которые могут задать на собеседовании
- *Зачем валидировать данные схемой?* — Ошибки в данных дешевле ловить на входе, чем искать потом,
  почему модель плохо учится.
- *Зачем CI в учебном проекте?* — Чтобы каждое изменение автоматически проверялось и сломанный код
  не оставался незамеченным.
- *Почему ключи не в коде?* — Репозиторий публичный; ключ в коде = ключ у всех, и его историю
  из git уже не вычистить.
